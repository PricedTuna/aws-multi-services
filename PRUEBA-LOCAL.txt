 GUIA: PROBAR recordatorios-diferidos EN LOCAL (SAM)
 Archivo: PRUEBA-LOCAL.txt

Requisitos previos
------------------
  - Docker instalado y en ejecucion.
  - AWS CLI configurado (aws configure / aws sso login).
  - SAM CLI instalado.

----------------------------------------------------------
 PASO 1. Levantar DynamoDB Local
----------------------------------------------------------
Solo es necesario si el contenedor no esta corriendo.
Si reiniciaste la PC, el contenedor sigue existiendo pero
apagado; verifica su estado:

    docker ps -a --filter name=dynamodb-local

  * Si aparece con STATUS "Exited"  ->  docker start dynamodb-local
  * Si NO aparece (lo borraste)     ->  crearlo de nuevo:

        docker run -d --name dynamodb-local \
          -p 8000:8000 \
          -v ~/.dynamodb-local/data:/home/dynamodblocal/data \
          amazon/dynamodb-local \
          -jar DynamoDBLocal.jar -dbPath /home/dynamodblocal/data

    (Las tablas persisten en ~/.dynamodb-local/data,
     no se pierden al reiniciar.)

Verifica que DynamoDB Local responde:

    aws dynamodb list-tables --endpoint-url http://localhost:8000
    # -> Debe mostrar: RemindersProductionTable

  !! Si la lista sale vacia, crea la tabla:

    aws dynamodb create-table \
      --endpoint-url http://localhost:8000 \
      --table-name RemindersProductionTable \
      --key-schema AttributeName=id,KeyType=HASH \
      --attribute-definitions AttributeName=id,AttributeType=S \
      --billing-mode PAY_PER_REQUEST

----------------------------------------------------------
 PASO 2. Construir la Lambda
----------------------------------------------------------
Desde la raiz del proyecto:

    sam build

----------------------------------------------------------
 PASO 3. Invocar CreateReminderFunction en local
----------------------------------------------------------
    sam local invoke CreateReminderFunction \
      --event events/create-event.json \
      --env-vars local-env.json

  Resultado esperado: { "statusCode": 201, ... }

----------------------------------------------------------
 PASO 4. (Opcional) Invocar GetReminderFunction en local
----------------------------------------------------------
Copia el "id" devuelto en el paso 3 dentro de events/get.json
y ejecuta:

    sam local invoke GetReminderFunction \
      --event events/get.json \
      --env-vars local-env.json

----------------------------------------------------------
 PASO 5. (Opcional) Ver los registros guardados
----------------------------------------------------------
    aws dynamodb scan \
      --table-name RemindersProductionTable \
      --endpoint-url http://localhost:8000

----------------------------------------------------------
 NOTAS IMPORTANTES
----------------------------------------------------------
  - local-env.json apunta las funciones a DynamoDB Local:

        TABLE_NAME = RemindersProductionTable
        AWS_ENDPOINT_URL_DYNAMODB = http://172.17.0.1:8000

    (172.17.0.1 es la IP del bridge de Docker; "localhost" no
     funciona dentro del contenedor SAM en Linux.)

  - AWS_ENDPOINT_URL_DYNAMODB esta declarado (vacio) en
    template.yaml. Es necesario para que SAM lo inyecte al
    hacer override con local-env.json. En la nube no tienes
    que preocuparte: el valor vacio hace que el SDK use el
    endpoint real de AWS.

----------------------------------------------------------
 ARCHIVOS RELACIONADOS
----------------------------------------------------------
  - template.yaml          Definicion de los recursos (SAM).
  - samconfig.toml         Configuracion de SAM (stack, build, deploy).

  - events/create-event.json  Evento de prueba para CreateReminderFunction.
  - events/get.json           Evento de prueba para GetReminderFunction.
